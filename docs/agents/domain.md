# Domain docs

This repository uses a single-context domain layout.

Before exploring a domain area, read root `GLOSSARY.md` if it exists and relevant decisions in `docs/adr/` if they exist. Their absence is expected in this greenfield repo. `/domain-modeling` creates them when terms or decisions are resolved.

Use glossary terms in issue titles, specs, tests, and code. If a needed term is missing, reconsider it or raise the gap for `/domain-modeling`. If proposed work conflicts with an ADR, call out that conflict explicitly.

`idea.md` remains the founder's current product intent. If another document conflicts with it on unresolved founder intent, surface the conflict for a decision.
